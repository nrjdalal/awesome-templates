| `/fix-bug` proves the bug exists before it fixes anything | `/fix-bug` hardening | The four canonical phases are untouched (they are pinned by `target-operating-model.md` lines 22/24), but Phase 1 now **branches before any test is written**: a confirmed failure obliges a red test asserting the *specific* failure mode, a disproved causal claim exits `not-a-bug`, and anything weaker exits `cannot-reproduce` — neither exit writes production code or a test. `not-a-bug` is deliberately narrow (an authoritative contract calls the behaviour intended, or the claim is disproved in the same environment **and** code path); "I could not make it fail" is explicitly not enough, which is the #401 shape. Phase 2 adds the **Cause Impact Matrix** — candidate / reachability evidence / disposition / evidence, with a termination condition — and that is what bounds test additions to what the root cause actually reaches, replacing the open-ended "also write edge-case tests" framing the work started from. Every run emits a `Bug Fix Report` carrying **`Outcome`** (`fixed` / `partial` / `not-a-bug` / `cannot-reproduce`), deliberately **not** the review protocol's `Verdict`: ADR 053 scopes that vocabulary to the three review skills and a fourth consumer would have created a second verdict semantics. A documented Small-Bug Lane carries the common one-line bug with an explicit step-by-step delta table rather than an exception token — `[trivial]` is wrong for a behaviour bug because a regression test is required.
