| Feature | Issue | Impact |
|---------|-------|--------|
| Harness hook tests load by path, and a guard that tested itself | #401 (PR #402) | Eight hook basenames exist in more than one harness copy (`verify_first.py` and `completion_gate.py` in all three, differing by 228 lines), so `import verify_first` names three files and `sys.modules` picks one. **The defect this was filed for did not exist**: the tier-2 tests already popped the bare key with `.claude/hooks` at `sys.path[0]`, and the third import (`user_prompt_submit`) does not collide at all because the other copies spell it with hyphens. The filing rested on reading the *end state* of `sys.modules` as what an earlier test used. What was real: that correctness came from an unstated `pop` + path pair, and the next test to omit either half would pass while exercising another harness. So the three bare imports load by path under `claude_*` / `codex_*` aliases — which tier 3 and the Codex tests in the same file already did — and an AST guard forbids the pattern, verified to fail first. **The pollution itself is unfixable from the test side**: hook files import their own siblings by bare name, correct for a standalone hook process, colliding only inside a shared pytest process. Cross-tool review then found the guard **reproduced the loading logic instead of calling it**, so a regression to a dynamic `importlib.import_module(name)` would have passed both the AST rule and the guard; it now calls the real loader and fails 3 of 5 when that regression is simulated. Two more review findings were mine: the guard mutated a `sys.modules` key it did not own without restoring, and its docstring resurrected the premise the work had disproved. |
| Typing `tests/` found six production defects | #394–#399 | The gate went from `src` + tooling to the **whole repository: 944 files, 0 errors**, and `tests/` was the last piece — 155 findings, none of them test noise. What it surfaced: a `cast(list[BaseModel], entities)` in `BaseService.create_datas` that existed **only** because `list` is invariant, deleted by widening `insert_datas` / `batch_put_items` to `Sequence[BaseModel]` (the vector store already had it); three functions asking for a class where they use one member, including an audit logger that demanded a whole repository to call `insert`; and **two doubles that had silently stopped matching the protocols they impersonate** — `MockUserRepository` missing `count_datas_by_day` since #368, `FakeUseCase` still naming a parameter `user_id` that #218 renamed to `admin_id`. Neither was catchable before: a double that no longer matches its interface still runs. `tests/support/fake_repository.py` now declares the 13-member `BaseRepositoryProtocol` surface once, every member raising, so the next protocol change breaks **one file** instead of drifting silently through N doubles. Two limits were learned by getting them wrong: a `_SupportsProps` protocol whose method signature **excluded every real `Button`** (NiceGUI's `props` is a property returning a callable wrapper), and the concrete client annotations in `ObjectStorage` / `BaseS3VectorStore` that must stay concrete because they are what type-check the boto and aiohttp calls inside them — there the double is accepted at the substitution site instead. Suppressions went 21 → 52 and the pin caught itself counting a directive quoted in **its own docstring**. |
