| One type checker, whole repository — and two ways coverage lies | #381, #375, #387 (PRs #382–#386, #388, #390) | pyright went **91 errors → 0 across 684 files**, and mypy was **retired rather than repaired**: it aborted on a duplicate module name (`completion_gate.py` exists in two harness copies), so it reported one error and inspected *nothing* under `src/` — and because it was `stages: [manual]`, nothing ran it for two releases. Even repaired it would have been shallow: its only `additional_dependencies` were `types-requests` and `pydantic`, so every fastapi / sqlalchemy / nicegui type was `Any`. Retiring it therefore had to *widen* pyright, which is where the findings came from. **Two thirds of the remaining errors were AWS typing nobody had installed**: without `types-aioboto3` every `async with … .client()` resolved to an untypeable placeholder, and `S3VectorClient.client()` declared the generic `AioBaseClient` — whose `__getattr__` unconditionally raises, i.e. `NoReturn` — so **the four s3vectors calls had never been type-checked at all**. Real defects found and fixed, not suppressed: `make scheduler` **had never run the scheduler** (`run_scheduler` is a coroutine function and the call dropped it, so `audit_cleanup_task` never fired from the documented path); `list_files` subscripted an optional `Key`; `hasattr` used where it cannot narrow; a possibly-unbound local in the once-per-deployment setup flow; a fail-open stub whose signature did not match what it stands in for; and one name the harness `except` branch forgot to give a sentinel. **The two lessons are about coverage lying, not about types**: a stale allow-list fails nothing (it drifted twice, including during the closing sync), and a dot-directory named in `include` is skipped in silence while still printing `0 errors`. Both are now pinned by `tests/unit/tools/test_pyright_scope.py`, along with where the 21 remaining `# pyright: ignore` comments may live. 96 mypy-era `# type: ignore` comments were deleted and **zero** replaced by a pyright suppression. `tests/` was cleared separately in #394–#399 (155 → 0) and is now in the gate; two of its findings were doubles that had stopped matching the protocols they impersonate. |

The real finding: **the `--q-*` half of the token system had never taken effect.** NiceGUI writes its brand palette as an **inline style on `<body>`**, which outranks every stylesheet rule regardless of specificity, so `theme.py` declaring `--q-*` in `:root` was inert from #193 through #235 — measured on `main` as `rootVar #2563eb` / `bodyVar #5898d4`. Every button, badge and `text-primary` rendered NiceGUI's defaults (pale blue, **teal** secondary, **purple** accent, **cyan** info) beside the `--admin-*` greys, i.e. a third palette on screen. That, not the `AdminColors` ramp-mixing the issue was filed for, is the larger reason admin colours never sat right. | Quickstart demo scripts: fail-loud + CI guard + GIF | #360, #361 | v0.10.0 repaired the auth in `scripts/demo.sh` / `demo-rag.sh` but left the mechanism that hid the breakage for two months: **printing a response is not checking it**. `demo-rag.sh` printed a 401 for every `/v1/docs/*` call and still exited 0; `demo.sh` did the same from `GET /v1/users` onward, sailing through five broken calls. | Audit cluster D — BaseRepository engine parity | #325 (PR #356) | **Two API-visible changes.** `insert_datas` committed and then read server-side defaults that were never loaded, so `MissingGreenlet` became `500 DB_INTERNAL_ERROR` **for rows already written** — invisible in CI because only MySQL/MariaDB set `insert_returning=False`. Offset pagination had no `ORDER BY`, so pages could repeat or skip rows; the PK descending is now a tiebreaker on **every** paged query including one carrying an explicit `sort_field` (the first fix skipped it there, which put tie order back in the engine's hands). Search over no usable text column now raises `400 DB_SEARCH_FIELD_UNUSABLE` instead of returning the whole table with `total_items` set to the full count, and an unknown `sort_field` is `400 DB_UNKNOWN_FIELD` instead of an opaque 500. [ADR 058](../../docs/history/058-base-repository-engine-guarantees.md) records the guarantee **and its limit: no real MySQL runs in CI** — D1 is pinned by forcing `insert_returning=False` on SQLite. Six domains and nine examples inherit this class, so each defect shipped N times. |

| Audit clusters L+C+A — the inline broker was a different runtime | #324, #326, #330 (PRs #342, #343, #340, #338) | `BROKER_TYPE=inmemory` is the shipped default and runs `.kiq()` inside the server process — with an **empty middleware stack** and unresolved `Provide[...]` markers, so retries, error logging, structlog context and #310's worker alerts were all inert and docs ingestion silently no-opped. The server now installs the same stack and domain DI wiring on the inline broker. Separately, admin built its **own** `CoreContainer`: two async engines, two `QueuePool`s, two `HttpClient`s and two `ErrorNotifier` cooldown dicts per process, so an HTTP-path alert did not suppress its admin-path duplicate. | Audit clusters F+B+M+N+E — fail-closed everywhere | #323, #327, #328, #329, #322 (PRs #339, #345, #354, #355, #337, #344) | One rule applied across five subsystems: a request that cannot be honoured fails with a curated 4xx rather than silently returning something else. | Error Notification Channel Routing | #286 (PR #313), #315 (PR #319) | Adds optional severity-based channel routing on top of #17/#310. `NOTIFICATION_WARNING_THRESHOLD` is the **sole switch** — set below `NOTIFICATION_SEVERITY_THRESHOLD` it lowers the alerting floor to `min(severity, warning)` (`ErrorNotifier._effective_min_threshold`) and `NotificationRouter.resolve()` picks the tier client (`None` = do-not-dispatch). `NOTIFICATION_CRITICAL_WEBHOOK_URL` / `NOTIFICATION_WARNING_WEBHOOK_URL` are per-tier overrides that each fall back to the single provider webhook; they do **not** enable routing and are rejected at boot without the threshold (#315 — that combination previously booted and silently sent every alert to the base webhook). Cooldown key becomes `{tier}:{error_code}`, composing with #310's task prefix to `{tier}:{task_name}:{error_code}` — a bare key let a warning-tier 4xx mute a critical-tier 5xx, reachable with no subclass since `BaseCustomException` takes both args per instance. `CoreContainer` now holds four notification Selectors; the three client ones share **one** `_noop_notification_client` Singleton so the disabled path still logs `notification_client_disabled` exactly once (pinned by test), while `notification_router` declares `providers.Object(None)` on its `disabled` branch and therefore resolves to `None`. External contributor; 3 maintainer review rounds. |
| Worker Error Notifications | #310 | Extends error-notification dispatch to Taskiq task failures via `TaskFailureNotificationMiddleware` (`_core/infrastructure/notification/taskiq_middleware.py`), closing the surface #311 documented as a coverage limit. No new env vars — reuses `NOTIFICATION_*`. Worker specifics: severity is synthesised (`BaseCustomException` keeps its `status_code`, else 500) so `NOTIFICATION_SEVERITY_THRESHOLD` still applies; the cooldown key is scoped `{task_name}:{error_code}` so one noisy task cannot mute the rest; alerts fire once per incident on the terminal failure (permanent errors immediately, retryable ones after the last attempt). Middleware registration order is load-bearing and pinned by tests — taskiq runs `on_error` over `reversed(middlewares)` and the retry middleware mutates `_retries` in place. NiceGUI admin exceptions resolved as an explicit **non-goal** (operator-attended). Also closes #311's deferred R4: negative tests now pin that 422 / `HTTPException` never dispatch. |
| Error Notification Webhooks (contributor) | #17 (PR #304) | Adds optional error-notification core infra — the **first `src/` runtime feature after v0.9.0**. Slack/Discord webhook adapters + `NoopNotificationClient` fallback behind the ADR 042 Protocol + Selector pattern (`NOTIFICATION_PROVIDER` + matching webhook URL enable it; `BaseNotificationProtocol` in `_core/domain/protocols/`). `ErrorNotifier` gates by `NOTIFICATION_SEVERITY_THRESHOLD` (default 500) + a per-process, per-error_code `NOTIFICATION_COOLDOWN_SECONDS` (default 60) and dispatches fire-and-forget (`asyncio.create_task` — never awaited in the request path; send failures logged `exc_type`-only so the secret webhook URL never reaches logs). Hooked into `custom_exception_handler` + `generic_exception_handler` via `app.state.container` at runtime (no infra import in the exceptions module; dispatch never raises into the response path). Adapters POST via the shared `HttpClient` and never JSON-parse webhook responses (Slack success body is plain-text `ok`, Discord returns `204`). Settings validation follows the existing partial-config-group pattern (unknown provider / missing webhook URL rejected at boot, tested). Channel routing deferred to #286 (shipped in PR #313). 3-round review (Codex bot + 2 protocol rounds; all finding keys FIXED at merge). |
